## 1. 무엇 (핵심 두 축)
1. **에이전트-자기서술 상황판**: 에이전트가 스스로 굽는 🎯목적·🗺여정지도·인터럽트 스택·용어·결정·대기. 개발자용 *계측*이 아니라 사람 인지 보조용 *서사*(← 시장 빈틈, 정찰 F 확인).
2. **★분기 시각화 (킬러 차별점, Mark 아이디어)**: 여정 지도의 분기점에서 **실제로 에이전트를 분기시켜**(worktree/병렬 서브에이전트) 각 갈래를 병렬 개발하고, 패널이 그 **분기·진행·수렴을 라이브로 그린다**. = 프론티어 F1 "격리된 병렬 탐색"(다중 에이전트가 옳게 쓰이는 케이스) + 시각 + 사람 감독의 융합. **agentic-os v2도 여기까진 없다 → 우리가 한발 앞.**

## 2. ★★승부처 = agent-agnostic (Mark "에이전트 상관없이 쓸 수 있는 스킬")
- **어떤 에이전트든(Claude Code·Codex·Cursor·기타) 꽂으면 자동으로 상황판이 굽혀야** 한다. 이게 dead-simple하면 퍼지고, 손으로 JS 짜야 하면 죽는다(내 초기 분석+Mark 통찰 일치).
- **통합 경로 = MCP 서버**(1순위): 에이전트가 `set_goal`·`add_branch`·`update_branch_status`·`push_interrupt`·`lock_term`·`decide` 같은 도구를 호출→패널 상태 갱신→standalone 웹뷰가 라이브 렌더. MCP는 Claude/Cursor/Codex 다 붙는 현대 표준 = 벤더 무관 자동 달성.
- 대안: 얇은 CLI/라이브러리(MCP 못 쓰는 환경). 하지만 MCP가 "아무 에이전트나"에 제일 가깝다.

## 4. 성공조건 / 검증
- **통합 dead-simple 실증**: 생판 다른 에이전트(예: Cursor)에 MCP 한 줄 꽂아 패널이 자동으로 갱신되는가. (안 되면 제품 아님.)
- **분기-viz 실증**: 실제 병렬 분기가 트리로 라이브 그려지는가.
- 이 둘이 P0 검증 게이트. 둘 다 서면 "고도화 계속+배포 준비", 하나라도 막히면 재설계.

## 5. 정직한 현실 (하이프 아님)
- **agentic-os = 별 8개**(킬러 피치+완성 구조인데도). 이 판에서 주목은 좋은 것만으론 안 온다 — **예외적이어야.** 우리의 예외 후보 = *분기-viz* + *진짜 agent-agnostic*. 이 둘이 없으면 "또 하나의 대시보드"로 묻힌다.
- 네이티브(Claude Artifacts·ChatGPT Canvas)와 옆-패널 자리 경쟁. 우리 차별 = "에이전트가 굽는 상황+분기"이지 "콘텐츠 캔버스"가 아님 — 이 경계를 프레이밍이 지켜야.
- **배포는 L5**: 실제 공개·계정·게시는 Mark 집행. 나는 그 앞까지.
