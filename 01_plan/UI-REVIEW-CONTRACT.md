# OlchiPanel 디자인·UI 판단 절차

2026-09-08 사용자 승인: 요청을 구현하는 데서 끝내지 않고 디자이너와 UI 담당자의 시선으로 먼저 판단하고 스스로 검수·수정한다.
공통 판단 정본은 `C:/OlchiProjects/olchi-commons/ui-directions/UI-REVIEW-CONTRACT.md`이며 모든 UI 작업에 적용한다. 이 문서는 OlchiPanel의 기기 조건과 비교 사례를 보완하는 프로젝트 적용 문서다.
최신 사용자 지시 > AGENTS.md > 이 절차와 사례 순으로 적용한다.

## 시작: 구현 전에 판단한다

`human-ui-second-look`을 적용하고 `olchi-ui-direction`에서 관련 방향을 회수한다. 오류 수리는 `olchi-error-notes`에서 관련 원인을 확인한다. 스킬 이름을 열거하는 것으로 검토를 대체하지 않는다.

작업 메모 또는 짧은 진행 설명에 다음을 남긴다. 작은 수정은 네 문장이면 충분하다.

1. 누가 어떤 화면에서 무엇을 하려는가? 현재 대상은 컴퓨터·노트북의 Electron 앱이다.
2. 무엇이 먼저 읽혀야 하며, 각 표시를 사용자는 어떤 의미로 받아들이는가?
3. 요청을 문자 그대로 구현한 안과 실제 사용 흐름을 완성한 안은 어떻게 다른가? 선택한 이유와 대가는 무엇인가?
4. 사용자 행동 뒤 무엇이 바뀌고 무엇이 유지되어야 하는가? 새 데이터와 재방문까지 확인할 완료 조건은 무엇인가?

명백하고 되돌릴 수 있는 후속 동작은 요청 범위 안에서 함께 구현한다. 불필요한 선택 질문을 만들지 않는다. 불확실한 취향, 데이터 삭제, 외부 실행은 추정으로 승인하지 않는다.

## 디자이너 검토: 무엇을 어떻게 보게 하는가

- 실제 화면 전체를 보고 제목·주요 내용·상태·보조 동작 순으로 읽히는지 판단한다.
- 비율·정렬·여백·밀도를 함께 본다. 가로 넘침이 없더라도 글과 열이 비좁으면 통과가 아니다.
- 배경·테두리·색·그림자 각각이 구분이나 행동에 필요한 이유가 있는지 확인한다. 익숙한 카드 템플릿을 자동 적용하지 않는다.
- 반대로 장식을 줄인다며 필요한 그룹 경계와 선택 표시를 없애지 않는다.
- 요청한 요소와 인접 메뉴·본문·대화상자를 함께 본다. 서로 같은 의미인 제어는 일관되게 표현한다.
- 작은 수정은 합의된 사례를 사용한다. 큰 디자인 변경은 적용 가능한 UI production 절차와 사용자 선택 레퍼런스를 따른다.

## UI 담당자 검토: 행동 뒤에도 맞는가

- 사용 전 → 행동 → 결과 → 이탈·재방문을 실제로 수행한다.
- 해당 기능에 관련된 빈 상태·긴 내용·새 데이터·저장·실패·재실행·세션 전환을 선택해 검증한다. 모든 작업에 무관한 테스트를 덧붙이지 않는다.
- 선택, 키보드 포커스, 읽음, 완료, 해결됨을 혼동하지 않는다. 포커스 표시는 디자인 단순화 때문에 제거하지 않는다.
- 버튼을 누르면 이름에 맞는 유용한 결과가 있어야 한다. 복사 버튼은 실제 복사 내용을, 저장은 재방문한 값을 확인한다.
- 화면에 보이지 않은 항목과 비활성 창의 데이터를 읽음 처리하지 않는다. 동작이 없는 버튼이나 근거 없는 다음 작업을 만들어 넣지 않는다.

## 종료: 자체 수정 후 보여준다

1. AGENTS.md의 실행 수명주기와 앱 1창 원칙을 지키고 실제 앱을 검수한다. 코드·DOM 검사만으로 시각 검수를 대체하지 않는다.
2. 디자이너 관점의 구체적 관찰과 UI 담당자 관점의 행동·결과를 각각 남긴다. 필요한 스크린샷과 측정·테스트 포인터를 연결한다.
3. 발견한 가독성·위계·상태 전이 문제를 범위 안에서 먼저 수정하고 영향받은 검사를 다시 한다. 개선점을 억지로 만들거나 끝없는 미세 조정을 하지 않는다.
4. 검수 불가 항목은 미확인으로 남긴다. 수정 결과와 검증 범위를 짧게 보고하고, 사용자 최종 평가와 구현 검증을 구분한다.

짧은 검수 메모 형식:

```text
목적 / 선택 이유:
디자이너 관찰: 실제 보이는 위계·구분·여백과 증거
UI 담당자 확인: 수행한 행동 → 실제 결과 → 재방문 결과
발견 문제 / 자체 수정 / 재확인:
남은 미확인 또는 사용자 판단:
```

새 피드백은 "대상·거부한 안·원하는 결과·이유·예외·증거·사용자 확인 여부"로 추가한다. 한 사례를 전역 금지 규칙으로 확대하지 않는다. 사건은 오답노트, 반복 적용할 판단은 UI 방향으로 나누되 작업 시작에서 실제 회수되는 연결을 유지한다.

### 2026-09-08 E2 선택 피드백
사용자는 E2 Studio Console을 선호하며 다크·대응 라이트를 요청했다. E2 선택 표식은 작은 정사각형 대신 가늘고 긴 직사각형(3×18px)으로 갱신한다. 투명한 선택 배경과 별도 키보드 포커스 원칙은 유지한다.

후속 교정: 세션은 두 줄 정보 높이에 맞는 34px 왼쪽 표식, 사이드바는 18px, 본문 가로 탭은 아래 밑줄을 사용한다. 선택 상태라는 이유만으로 서로 다른 정보 계층의 크기·방향을 동일하게 만들지 않는다.

### 지연 안내 선호 (2026-09-08)
상시 사용법 문구 대신 해당 탭에 1초 hover 또는 키보드 포커스하면 안내한다. 실제 상태·오류·필수 행동은 숨기지 않는다. LED는 프로젝트명 왼쪽 전용 칸에 배치하고 X 보관 버튼과 분리한다. 연결은 초록, 연결 안 됨은 회색, 실제 응답 중만 스피너다.

### 2026-09-20 메뉴·라벨 교정과 전체 테마 제안

최신 사용자 지시: 공통 노트는 숫자0 대신 1 왼쪽 물리 Backquote 키로 연다. 입력 중에는 동작하지 않는다. 메뉴 글자/키캡과 왼쪽 선택 표식은 유지하고 행 간격을 줄인다. 라벨은 의미별 색 차이와 채워진 보드 배지, 체크 표시로 구분한다.
