# OlchiPanel 컨시어지 검증 — 시나리오 + 질문지 (비개발자 대상)

작성: 2026-07-29 · 오너: `Master_D_Fable` · 상태: **검증 도구(내부, 미공개)** · 근거: Mark 전략("챗봇만 쓰는 비개발자에게 로컬 번들을 싸게, 진입장벽을 낮춰 파는 틈새 전략")

## 0. 이 테스트가 답하려는 것 (짓기 전에 죽일 수 있는 가설)

우리는 **1클릭 설치본을 만들기 전에** "가치가 있는가"만 시험한다. 설치가 장벽인 건 이미 안다 — 그래서 우리가 설치를 대신 해준다(컨시어지). 순수하게 **가치·신뢰·지불의사**만 본다.

| 가설 | 성립하면 | 깨지면 |
|---|---|---|
| **H1 가치** — 비개발자가 "AI가 내 PC에서 실제 일을 해준다"를 챗봇보다 가치 있게 느낀다 | 계속 | 중단(챗봇으로 충분하면 살 이유 없음) |
| **H2 신뢰(차별점)** — 상황판(뭘 하는지 다 보임)이 "AI가 내 컴퓨터 건드리는" 두려움을 신뢰로 바꾼다 | 이게 우리 무기 | 패널이 그냥 장식이면 차별점 없음 |
| **H3 지불** — 이 층이 소액을 낼 의향이 있다 | 틈새 사업 가능 | 무료만 원하면 사업 불가 |
| **H4 잔여 장벽** — 우리가 다 세팅해줘도 어디서 헤매는가 | 1클릭 제품이 반드시 없애야 할 지점 목록 | — |
| **H5 비용 진입장벽** — API 키·충전·종량제 토큰 청구 없이 자기 모델 구독 안에서 쓰는 방식이 이해되고 매력적인가 | 핵심 포지셔닝 | 구독 한도 소비가 더 큰 거부감이면 재설계 |

**판정은 세션 전에 정한다(사후 합리화 금지).** 아래 §7 참조.

## 1. 참가자 모집 기준 (진짜 대상층)

- **필수**: ①챗봇(ChatGPT 등)을 가끔이라도 쓴다 ②개발 상식 전무(터미널·설치·코딩 경험 0) ③Windows PC 사용 ④컴퓨터로 귀찮은 반복 일이 있다(사진·문서·정리·조사).
- **제외**: 개발자·IT 종사자·"컴퓨터 잘하는 사람"(우리 대상 아님).
- **분산**: 연령·컴퓨터 친숙도 폭넓게. 지인 편향 주의(Mark가 아는 사람이면 "잘 봐주려는" 호의 편향을 감안).
- **표본**: **5~8명**(질적 검증 표준 — 패턴이 보이는 최소치). 3명에서 벌써 같은 벽이 3번 나오면 그 자체가 신호.

## 2. 사전 세팅 (컨시어지 = 우리가 다 함, 참가자는 못 봄)

- Mark가 **참가자 PC(또는 대여 노트북)에 미리** 전부 설치·설정·에이전트 연결. 참가자는 **터미널·설정·용어를 절대 보지 않는다.**
- 참가자에게 보이는 것: **패널 창 + 말 거는 입력칸** 딱 두 개.
- **안전 필수**: ①시작 전 참가자 데이터 백업 ②작업은 **샌드박스 폴더** 안에서만 ③삭제·비가역·외부 발송·계정/결제 작업 금지 ④실제 비밀번호·개인정보 미사용 ⑤언제든 중단 가능. (비개발자는 위험을 판단 못 하므로 우리가 울타리를 친다.)

## 3. 세션 흐름 (45~60분, think-aloud)

**진행자 규율: 팔지 마라. 유도하지 마라. 침묵을 견뎌라.** 참가자가 헤매도 3초 기다린 뒤 최소 개입.

- **0. 동의·백업·안내(5분)**: "정답 없어요. 생각을 소리 내어 말해주세요. 제품을 평가하는 게 아니라 여러분을 관찰하는 거예요."
- **1. 베이스라인(7분, Mom Test)**: 제품 얘기 금지. 실제 삶을 묻는다.
  - "평소 ChatGPT를 어떻게 쓰세요? 마지막으로 쓴 게 언제, 뭐였어요?"
  - "컴퓨터로 하기 귀찮아서 미뤄둔 일이 있어요? (사진 정리, 서류, 자료 찾기 등)"
  - "그거 지금은 어떻게 처리하세요? 시간 얼마나 걸려요?"
  - → **실제 아픔과 현재 대처 비용**을 캔다.
- **2. 첫 접촉(침묵 관찰, 5분)**: 앞에 앉히고 최소한만: *"이건 여러분 컴퓨터에서 일을 대신 해주는 AI예요. 이 화면은 그 AI가 지금 뭘 하는지 보여줘요. 하고 싶은 걸 그냥 말해보세요."* — **개입 없이 본다**: 뭘 칠지 아는가? 패널을 보는가?
- **3. 진짜 일(15분)**: §1에서 참가자가 말한 **자기 일**을 시킨다(없으면 준비된 안전 과제: 폴더 사진 날짜별 정리 / 파일 이름 정리 / 폴더 문서 요약 / 편지 초안). 에이전트가 **실제로 일할 때** 반응을 본다.
- **4. 신뢰 프로브(5분)**: 에이전트가 뭔가 하려는 순간에: *"지금 이게 이걸 하려는데, 어떤 기분이에요?"* — 패널이 안심을 주는지 본다.
- **5. 벽 관찰(5분)**: 스스로 두 번째 일을 시도하게 둔다. 어디서 막히는지 기록(H4).

## 4. 관찰 시트 (묻지 말고 봐라 — 행동 신호)

세션 중 진행자/기록자가 **말이 아니라 행동**을 채운다:

- [ ] 시키지 않았는데 **패널을 봤나?** 몇 번? 언제(에이전트가 움직일 때? 불안할 때?)
- [ ] 에이전트가 **실제로 뭔가 했을 때** 표정·말: 😀놀람/기쁨 · 😨두려움 · 😕혼란 · 무반응
- [ ] **어디서 막혔나**(우리가 개입해야 했던 지점) — 1클릭 제품이 없앨 목록
- [ ] 결과를 **믿었나**, 아니면 불안하게 확인했나?
- [ ] **스스로 두 번째 일**을 시도했나? (재사용 의욕 = 진짜 가치 신호)
- [ ] "이거 나도 쓸 수 있겠다" vs "나한텐 어렵다" 중 무의식 발화?

## 5. 인터뷰 질문지 (세션 후, Mom Test — 유도 금지)

**금지**: "이거 쓰실래요?" "얼마면 사실래요?" "좋았어요?"(전부 거짓 긍정 유발). **대신 과거·구체·행동을 묻는다.**

**가치(H1)**
- "방금 한 것 중에, ChatGPT로는 **못 하던 게** 뭐였어요?"
- "이걸로 대신 하고 싶은, 평소 진짜 귀찮은 일이 떠올라요? 구체적으로."

**신뢰(H2)**
- "AI가 일하는 동안 **뭘 보고 있었어요?** 왜요?"
- "AI가 내 컴퓨터에서 일한다는 게 어떤 기분이에요? 불안했던 순간이 있었나요? **뭐 때문에** 불안/안심했어요?"
- (패널 언급이 자발적으로 나오는지가 핵심 — 우리가 "패널 어땠어요?"라고 물으면 오염됨. 안 나오면 H2 약함.)

**지불(H3) — 간접 먼저, 직접은 맨 끝에 부드럽게**
- "요즘 **돈 내고 쓰는 앱·구독**이 있어요? (넷플릭스, ChatGPT Plus 등) 마지막으로 결제한 게 뭐였고 왜 냈어요?" → 실제 지불 행동 앵커.
- (맨 끝) "만약 이게 유료 앱이라면 — **얼마면 '이건 당연히 사지' 싶고, 얼마면 '너무 비싸다', 얼마면 '이렇게 싸면 오히려 못 미덥다' 싶어요?"** (가격 4점 감각 — 숫자를 우리가 먼저 던지지 않는다.)

**비용 구조(H5) — 가격 질문 뒤에만 공개**
- 중립 설명: "이 제품은 API 키를 만들거나 작업별 API 토큰값을 따로 내는 방식은 아닙니다. 본인이 쓰는 지원 모델 구독 안에서 작동하고, 그 구독의 사용 한도는 같이 소비됩니다."
- "이 설명을 듣고 실제로 어떤 비용을 내는 구조라고 이해하셨어요?" → 말 그대로 재진술하게 해 오해를 찾는다.
- "API 키·종량제 결제가 없는 점과 구독 한도를 같이 쓰는 점 중 어느 쪽이 선택에 더 크게 영향을 줘요? 왜요?"
- “공짜”, “무제한”, “추가비용 0”이라는 오해가 나오면 H5는 이해 실패로 기록한다.

**잔여 장벽(H4)**
- "제가 없이 혼자 이걸 깔아서 써야 한다면, 어디서 막힐 것 같아요?"

## 5-B. 두뇌 비교 프로브 (비용 모델 실측 — `BRAIN-COST-MODEL.md` 연동)

가치 검증과 **같은 세션에서** 두뇌 비용 모델의 미상 3개를 실측한다(별도 테스트 불요):

- **세팅**: 참가자별로 ①로컬 Qwen3-8B(Ollama) ②클라우드 저가(GPT-5.4 Nano급) **둘 다** 준비. 같은 과제(§3-3)를 양쪽으로 돌린다(참가자에겐 "두 방식" 정도만, 어느 게 로컬/클라우드인지 밝히지 않음 — 편향 방지).
- **기록**: ①과제 성공 여부(로컬이 실제로 해냈나 = 능력 요구치) ②클라우드 세션의 실 토큰 소모(캡 크기 근거) ③참가자 PC 사양(CPU·RAM·GPU — 로컬 감당 여부).
- **판정 입력**: 로컬이 과제 과반을 완수 → ③ 로컬(싸게/일회) 노선 근거 / 로컬이 자주 실패하거나 PC가 못 받침 → ② 클라우드+하드캡 또는 하이브리드.
- 이 절 결과로 `BRAIN-COST-MODEL.md`의 §2(토큰)·§3(손익)을 추정 → 실측으로 갱신한다.

## 6. 안전·윤리 (테스트 자체)

참가자의 실제 PC를 다룬다: **백업 선행 · 샌드박스 폴더 한정 · 삭제/비가역/외부발송/결제/계정 금지 · 실제 개인정보·비밀번호 미사용 · 화면 녹화는 동의 후 · 익명 처리 · 중단 자유.** 비개발자는 위험을 못 가리므로 **우리가 울타리를 책임진다.**

## 7. 판정 기준 (세션 전에 못박음 — 사후 합리화 금지)

- **GO 신호(계속)**: ①과반이 **패널을 자발적으로 보고** "이게 보여서 믿음이 간다"류 발화 ②과반이 진짜 일을 완수하고 "이건 ChatGPT로 못 하던 것"이라 인정 ③일부가 우리 하한 이상의 **가격을 스스로 제시**.
- **KILL 신호(중단)**: 챗봇 대비 가치를 못 느낌 / 패널이 신뢰로 안 이어짐 / 어떤 가격에도 지불 의향 없음.
- **비용 메시지 게이트**: 과반이 “API 키·종량제 청구 없음”과 “내 구독 할당량 소비”를 모두 정확히 재진술해야 한다. 한쪽만 이해하면 카피·온보딩 FAIL이며 가치 GO와 별개로 교정한다.
- **무엇이든 산출**: 1클릭 제품이 **반드시 없애야 할 상위 3개 벽**(H4).
- 표본이 작으므로 "숫자"보다 **패턴의 일관성**으로 읽는다(같은 벽·같은 반응이 반복되는가).

## 8. 종합 (세션 후)

`Guidelines\research-synthesis-v0` 양식으로 묶는다: 발견마다 **빈도(몇 명)·영향(사업 파급)·신뢰도(직접관찰 vs 발화)·삼각검증(행동+발화+가격이 같은 방향인가)**. 발화만 긍정이고 행동은 아니면 신뢰도 낮음으로 표시. 결론은 H1~H4별 GO/KILL과 벽 3개.
