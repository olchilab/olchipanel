# OlchiPanel 소비자화 — 두뇌·비용 모델 결정 브리프

작성: 2026-07-29 · 오너: `Master_D_Fable` · 상태: **조사·설계(내부, 미공개)** · 근거: Mark 전략(챗봇만 쓰는 비개발자에게 저가·저장벽 로컬 번들)
라우팅: 지금은 Master 소유, 제품화로 굳으면 올치패널 프로젝트로 externalize.

> **정직성 경계**: 아래 단가는 실측(2026-07-29 스킬·웹), 토큰 소모·손익은 **추론 추정**이다. 진짜 값은 컨시어지 테스트에서 실측한다. 숫자를 확정으로 읽지 말 것.

## 0. 프레임 정정 (Mark 교정 2026-07-29 — 급소)

**초판 오류**: 종량제 API 단가로 계산했으나, 지금 올치팀즈/올치패널이 도는 방식은 **API 키 종량제가 아니라 「구독 로그인 → 구독 할당량 소비」**다. 에이전트(Claude Code·Codex)는 Mark의 구독(Claude Max/ChatGPT Pro)으로 로그인해 그 월 할당량을 태운다. 종량제 토큰값을 따로 내지 않는다.

**소비자 적용**: 사용자가 **자기 구독**(ChatGPT Plus/Claude Pro 등, 계정 로그인=OAuth, API 키 아님)으로 에이전트를 돌린다. 올치패널 작업은 그 구독에 공짜로 덧붙는 것이 아니라 **사용자가 내는 구독료 안에서 모델 할당량을 함께 소비**한다.

비용은 아래처럼 분리한다.

- 사용자 현금비용: 모델 제품 구독료 + 올치패널 제품료(유료일 때).
- 사용자 자원비용: 올치패널이 소비한 구독 할당량. 많이 쓰면 사용자의 일반 ChatGPT/Claude 작업 여유가 줄어든다.
- 우리 공급자 청구: 사용자 구독 경로라면 별도 API 청구가 없을 수 있으나, 이것을 “모델비용 0”이라고 표현하지 않는다.
- 로컬 경로: 모델 구독료 대신 하드웨어·전력·설치·대기시간을 사용자가 부담한다.

이미 구독 중인 사용자는 올치패널 때문에 당장 추가 결제가 없을 수 있다. 그래도 **총소유비용과 할당량 기회비용은 0이 아니다.**

### 제품 강점으로 쓰는 정확한 표현

> **API 키도, 종량제 API 토큰 청구도 없이. 이미 쓰는 지원 모델 구독 안에서 작동합니다.**

보조 설명:

> ChatGPT·Claude 등 지원되는 사용자 본인 구독의 사용 한도는 함께 소비됩니다. 구독료·한도·초기화 주기는 해당 모델 제품 정책을 따릅니다.

이 포지셔닝의 핵심은 세 가지다.

1. 비개발자가 API 키를 만들고 복사하고 충전할 필요가 없다.
2. 작업마다 별도 API 토큰 청구서가 쌓이지 않는다.
3. 각 사용자가 자기 모델 계정과 자기 구독을 사용하므로 올치패널이 모델 사용료를 재판매하지 않는다.

금지 문구:

- “AI 비용 0원”
- “무제한”
- “완전 무료”
- “외부 통신 없음” — 구독 모델은 클라우드 서비스와 통신한다.

공개 주장 전 확인할 것:

- 지원 CLI의 공식 구독 로그인 경로만 사용한다.
- API 키가 생성·노출·전달되지 않는 설치 흐름을 실증한다.
- 사용자별 계정 공유 없이 본인 로그인만 허용한다.
- 구독 한도 소진·제한 도달을 사용자에게 숨기지 않는다.
- 제3자 번들·자동화 사용의 기술·약관 허용 범위를 확인한다.

- "BYO 키=탈락"은 절반만 맞음 — **API 키 발급**은 장벽이나 **계정 로그인**은 저마찰(챗봇 유저는 계정 이미 보유 다수).
- 아래 §1~§3의 종량제 단가·손익은 **"구독 로그인이 막혔을 때의 대안(②·③) 계산"으로만** 유효하다. 1순위는 구독 로그인.

### 급소 미상 (반드시 실측/법무 확인 — 추측 금지)
**"우리가 번들한 제3자 앱에서 사용자의 소비자 구독 로그인으로 자동 에이전트 작업을 돌리는 게 기술적으로 되고 ToS가 허용하나?"**
- Claude Code를 Claude Pro로 쓰는 것 자체=공인. 하지만 **재배포·번들 + 소비자 구독 자동화**는 재배포 약관·자동화 제한·구독 rate limit에 걸릴 수 있음.
- 통과=사용자 구독료+할당량 소비 모델(우리 별도 API 청구는 없을 수 있음). 막힘=②캡 클라우드 또는 ③로컬로 회귀.
- 이건 조사·법무 확인 대상. Claude·OpenAI 각 소비자 구독 ToS와 Agent SDK/CLI의 계정 로그인 지원을 실측한다.

(참고: 종량제로 갈 경우에만) 비용은 구독료가 아니라 모델이 태우는 토큰이며 에이전트 작업은 토큰을 많이 태운다.

→ **클라우드 두뇌 1건 = 대략 $0.03~$0.50.** (캐싱·과제 편차 큼. 이 표가 손익을 좌우하므로 **컨시어지에서 실 세션 토큰을 측정**해 대체한다.)

## 3. 손익 시나리오 (저가 정액 가정)

**가정: 월 $5 저가 구독, 우리가 두뇌 제공(②안).**

| 사용 강도 | Haiku(무거움 $0.50/건) | Nano(가벼움 $0.03/건) |
|---|---|---|
| 월 10건 | 원가 $5.0 = 본전 | $0.3 = 흑자 |
| 월 30건(일 1회) | 원가 $15 → **적자 $10** | $0.9 = 흑자 |
| 월 100건 | 원가 $50 → **적자 $45** | $3 = 흑자 |

**교훈**: "싸게 + 우리가 원가 부담"은 **무거운 과제·헤비유저에서 마진 함정**. 살리는 법 = ①최저 두뇌(Nano급) + ②**하드 캡**(월 N건/N토큰, 최악 원가 < 가격) + ③캐싱.

**③안 로컬**: 공급자 모델 청구는 없지만 사용자 하드웨어·전력·설치·대기시간 비용이 남는다. $5/월 또는 **일회 구매** 가능성은 별도 가치·하드웨어 실측 뒤 판단한다. 단 (a)사용자 하드웨어가 받쳐야 하고 (b)품질이 약하다.

## 4. 세 모델 판정

| 안 | UX | 실제 비용 부담 | "싸게" 적합 | 치명 리스크 |
|---|---|---|---|---|
| ① 사용자 구독 로그인 | **낮음(API 키·충전 불요)** | 사용자 구독료+할당량, 올치패널 제품료 | **○** | 할당량 경쟁·번들 약관·구독 없는 사용자는 추가 결제 |
| ② 클라우드 제공+캡 | 최고 | 우리가 변동비 부담(캡 필요), 사용자는 제품료 | △ | 캡 없으면 마진 함정 |
| ③ 로컬 소형 | 좋음+프라이버시 | 사용자 하드웨어·전력·설치·대기시간 | **○** | 약한 PC에서 안 됨·품질 |

**Mark 최신 전략은 ① 사용자 구독 로그인 우선**이다. 제품 강점은 “API 키·종량제 API 토큰 청구 없음”이며, 사용자의 기존 구독 할당량 안에서 작동한다.

- 기본 = 사용자 본인의 지원 모델 구독 로그인.
- 폴백 = 로컬 Qwen3-8B(구독이 없거나 프라이버시·단순 작업 우선일 때).
- 별도 종량제 API = 위 두 경로가 안 되는 기능에만 제한적으로 검토.

## 5. 결정을 막는 실측 미상 (컨시어지 테스트가 답할 것)

지금 확정하면 안 되는 이유 — 아래 3개를 모른다:
1. **능력 요구치**: 비개발자 실제 과제를 **로컬 Qwen3-8B가 실제로 해내나?** (해내면 ③으로 싸게, 못 하면 ② 필요)
2. **실 토큰 원가**: §2 표를 실 세션으로 대체 — 캡 크기의 근거.
3. **대상 하드웨어**: 이 층의 값싼 노트북(통합그래픽·8GB)이 로컬을 **감당하나?** 상당수 탈락 예상 → 폴백 필요.

→ 컨시어지 테스트에서 **같은 과제를 로컬 vs 클라우드로 나란히** 돌려 (1)(2)를 측정하고, 참가자 PC 사양으로 (3)을 수집한다.

## 5-C. 로컬 Qwen3-8B 능력 실측 (2026-07-29, Mark 머신)

Ollama 0.32.5 + `qwen3:8b`(5.2GB)를 Mark PC(RTX 4070 Ti·32GB·Ryzen7)에 설치해 비개발자 과제 3종 실측:

| 과제 | 품질 | 속도 |
|---|---|---|
| 감사 편지 초안 | 따뜻·정중 3문단, 자연스런 한국어 — 만족 | 4.1s / 79 tok/s |
| 파일 정리 계획 | 정확한 Windows 단계 안내 | 15s / 78 tok/s |
| 문단 요약 | 깔끔·정확 3줄 | 1.5s / 79 tok/s |

**판정: 능력 충분(chat/추론).** 로컬 두뇌 폴백은 능력 근거로는 성립.

**미해결(정직)**: ①**능력≠agency** — 채팅만 검증, 파일을 실제 옮기는 도구 사용 에이전트 동작은 미검증(다음 단계=에이전트 하네스 물리기). ②**하드웨어** — 79 tok/s는 4070 Ti 값. 대상층 값싼 노트북(GPU 없음)은 CPU 2~8 tok/s거나 미구동 가능 → 미해결. 이 테스트는 능력만 답함. ③인코딩: 셸 cp949 한글 뭉갬 실측 → Python UTF-8 전송으로 회피(문서화 함정 재현).

→ §5 미상 갱신: #1(로컬 능력) chat 부분 해소·agency 미해소 / #3(대상 하드웨어) 여전히 열림.
설치물: Ollama + qwen3:8b는 Mark PC에 상주(제거 가능). 구독 로그인이 1순위이므로 이건 폴백 검증.

## 6. 권고 (순서)

1. **비용 모델을 지금 못박지 않는다** — 위 3개 미상이 결정을 규정한다.
2. 컨시어지 테스트에 **두뇌 비교 프로브**를 넣는다(로컬 Qwen3-8B + 클라우드 Nano 둘 다 세팅, 같은 과제, 토큰·성공·체감 기록).
3. 결과가 "로컬로 충분"이면 ③(싸게/일회 구매), "능력 부족"이면 ②(Nano+하드캡) 또는 하이브리드로 확정.
4. 구독 경로는 현금비용·할당량 소비·올치패널 제품료를 분리해 제시한다. “모델비용 0” 문구는 쓰지 않는다.
5. 외부 메시지는 “API 키·종량제 API 토큰 청구 없음”을 전면에 두고, 같은 화면에서 “사용자 구독 할당량 소비”를 명시한다.
6. 이 결정은 **Mark 사업 판단(L5)** — Master는 근거(숫자·실측)만 준비.
