1. 심사위원: 설치하지 않아도 1분 안에 문제·해결·AI 활용·실제 작동을 확인하고 싶다.
2. 처음 쓰는 사용자: 자기 OS와 에이전트에 맞는 안내 하나를 따라 5분 안에 패널을 띄우고 싶다.

“어떤 환경에서도 된다”는 검증 불가능한 약속은 하지 않는다. 대신 **공식 지원 조합은 실제로 통과시키고, 그 밖의 환경은 감지·설명·브라우저 탭 fallback으로 실패를 닫는다.**

## 2. 현재 실물과 주요 간극

### 이미 있는 것

- npm `olchipanel@0.8.2` 공개, 런타임 의존성 0개, loopback-only MCP/viewer.
- Windows 실제 PWA·단일창·아이콘·플랜 전체 폭·모바일 렌더 검증.
- GitHub Actions에서 Windows/macOS/Linux의 최소 MCP smoke 실행.
- Claude Code·Codex·Cursor 설치 설명과 Windows 제한 환경용 `npx.cmd` 안내.

### 제출 전에 반드시 닫을 것

- CI가 세 OS에서 `smoke.js`만 실행한다. 전체 `npm test`의 크로스플랫폼 증거가 없다.
- macOS·Linux의 실제 창 열기, fallback, 재실행, 단일창 흐름이 검증되지 않았다.
- Antigravity는 공식 MCP를 지원하지만 현재 README·원클릭 설정 대상에 없다.
- `package.json`의 Node `>=18`은 현재 EOL 런타임까지 허용한다. 공식 지원선과 CI 매트릭스를 현재 LTS에 맞춰야 한다.
- README 하단 상태가 아직 `v0.1 pre-release`라 실제 npm `0.8.2`와 모순된다.
- 로컬 도구라 심사위원이 즉시 열 수 있는 공개 데모 링크가 없다.
- 로컬 정본 `master`와 원격 정본 `main`, release workflow 사이의 반영 경로가 아직 닫히지 않았고 GitHub 쓰기 권한도 막혀 있다.

## 3. 지원 환경 계약

### Tier A — 제출 전 실제 PASS 필수

| OS | 런타임·브라우저 | 에이전트 | 완료 증거 |
|---|---|---|---|
| Windows 11 x64 | Node 22/24 LTS, Chrome 또는 Edge | Claude Code, Codex CLI | 깨끗한 사용자 프로필 설치→도구 확인→첫 패널→재실행 단일창 |
| macOS Apple Silicon | Node 22/24 LTS, Chrome + 기본 브라우저 fallback | Claude Code, Codex CLI | 친구 Mac 실물에서 같은 여정 녹화·로그 |
| Ubuntu 최신 LTS x64 | Node 22/24 LTS, Chrome/Chromium + `xdg-open` fallback | Claude Code, Codex CLI | 깨끗한 VM 또는 CI에서 같은 여정 |
| 위 세 OS | Node 22/24 LTS | Cursor, Antigravity | MCP 등록→도구 노출→명시 요청 후 첫 상태 기록 |

### Tier B — 명확한 안내와 fallback 필수

- 관리자 권한 없는 Windows: 공식 Node ZIP + `npx.cmd` 경로.
- Chrome이 없는 macOS/Linux: 전용 앱 창 대신 기본 브라우저 탭으로 열림.
- SSH·WSL·headless·CI: `OLCHIPANEL_OPEN=0`, URL 출력, 창 자동 실행 없음.
- 포트 6711 사용 중·stale viewer 기록·npm offline cache: 원인과 다음 명령을 오류에 표시.

### 명시적 비지원

- 로컬 프로세스를 실행할 수 없는 browser-only ChatGPT/Claude 세션.
- 휴대폰 단독 MCP 실행. 휴대폰은 공개 데모 열람만 지원한다.

## 4. 첫 성공 acceptance

모든 Tier A 조합은 새 프로필·새 프로젝트에서 다음을 통과해야 한다.

1. 저장소 clone 없이 `npx -y olchipanel@latest`로 패키지를 받는다.
2. OS와 에이전트를 고르면 복사할 명령 또는 설정 파일 위치가 하나만 나온다.
3. 에이전트 재시작 뒤 OlchiPanel 도구가 보인다.
4. “이 작업을 OlchiPanel로 추적해” 요청 전에는 파일·세션·viewer가 생기지 않는다.
5. 요청 뒤 목표·단계가 생기고 `npx olchipanel open`으로 패널이 열린다.
6. 동시 실행과 재실행에도 viewer와 앱 창이 하나만 유지된다.
7. 에이전트 종료·재시작 뒤 이전 프로젝트를 이어받는다.
8. 실패하면 10초 안에 원인과 다음 행동을 이해할 수 있고 false-success가 없다.

측정 기준: 첫 성공 5분 이내, 수동 설정 수정 1회 이하, 막힌 단계 0개. 3명의 블라인드 설치에서 2명 이상이 도움 없이 성공해야 RC를 승인한다.

## 6. 제출 내용의 중심 문장

### 해결하려는 문제

AI 에이전트가 긴 대화 속에서 무엇을 하고 어디서 막혔는지 사람이 다시 읽지 않고는 알기 어렵다. 작업이 분기되거나 대화 주제가 바뀌면 목표·결정·재개점이 쉽게 사라진다.

### OlchiPanel의 해법

에이전트가 MCP 도구로 목표·단계·분기·인터럽트·결정·요청을 직접 기록하고, 로컬 상황판이 이를 실시간으로 보여준다. 모델을 대신 호출하지 않으므로 별도 API 키가 없고 상태는 사용자 컴퓨터에 남는다.

### AI 활용 적절성

정해진 로그를 수집하는 모니터가 아니라, 일을 수행하는 AI 에이전트가 현재 맥락을 구조화해 사람에게 설명한다. Claude·Codex·Cursor·Antigravity 같은 MCP 클라이언트에 같은 도구 계약을 제공해 특정 모델에 종속되지 않는다.

## 7. 제출 승인 게이트

## 8. 하지 않을 것

- 마감 전 계정·결제·원격 동기화·모바일 MCP·멀티테넌시를 새로 만들지 않는다.
- 모든 OS/브라우저/에이전트를 검증 없이 지원한다고 쓰지 않는다.
- 공개 데모를 실제 로컬 MCP인 것처럼 속이지 않는다.
