# 올치패널 배포 준비도 — 범주 먼저, 그다음 딱 그만큼

작성: Master_D_Fable 2026-07-24 · Mark 발주("보안·아키텍처를 볼 줄 모른다, 개발자 체크리스트를 만들어줘")

## 0. 먼저: 이건 어느 범주의 소프트웨어인가 (모든 판단의 기준)

**올치패널 = 로컬 오픈소스 개발자 도구.** 이 범주가 "챙길 것"과 "무관한 것"을 정한다.
- 실행: 각자 자기 컴퓨터. **서버 운영 없음.**
- 네트워크: `127.0.0.1` 전용. **외부로 나가는 데이터 0.**
- 비즈니스: 무료 오픈소스. **계정·결제·데이터 보관 없음.**

> A개발자(과잉)도 B(방심)도 이 질문을 안 물었다. 범주를 정하면 뭘 챙길지가 자동으로 나온다.

## 1. 이 범주에서 반드시 챙기는 것 (전부 실측)

| 항목 | 상태 | 실측 근거 |
|---|---|---|
| 외부 노출 차단 | ✅ | `127.0.0.1`만 바인딩 (`viewer.js:133`) — 0.0.0.0 아님 |
| XSS 방어 | ✅ | 데이터는 `textContent` 렌더(`el()` 헬퍼), `innerHTML`은 비우기(`=''`)뿐 |
| 명령 injection | ✅ | `spawn` 배열 인자·`shell` 없음·url은 통제값(`127.0.0.1:port`) |
| 경로 조작 | ✅ | 세션 파일명 sanitize(`state.js:18`), `~/.olchipanel/` 아래만 |
| 데이터 유출 | ✅ | 외부 전송 코드 0곳. 전부 로컬 파일 |
| 공급망 | ✅ | 런타임 의존성 0개(`package.json`) — 공격 표면 0 |
| 리소스 누수 | ✅ | 세션 7일 자동정리(`cleanup`), SSE 클라이언트 정리 |
| 라이선스 | ✅ | MIT |
| 설치 가능성 | ✅ | 배포 리허설: 생판 프로젝트에서 `npx olchipanel` 실사용 |
| 로컬 평문 저장 경고 | ✅ | README에 명시(비밀값 쓰지 말 것) |
| 크로스플랫폼 | ⚠️ | Windows 실측 완료 / **mac·linux 미측정** — 순수 Node라 설계상 되나 미검증 |

## 2. A개발자가 겁주지만 이 범주엔 무관 (왜 무관한가)

| 겁주는 항목 | 왜 무관 |
|---|---|
| 트래픽·스케일·로드밸런싱 | 서버 운영 안 함. 각자 로컬 1명 |
| DDoS·rate limiting | localhost. 외부 접근이 물리적으로 불가 |
| 인증·인가·세션관리 | 로그인 없음. OS 파일 권한이 경계 |
| HTTPS·TLS | 네트워크를 안 탐(localhost) |
| DB·백업·마이그레이션 | JSON 파일, 사용자 홈 |
| 멀티테넌시·격리 | 단일 사용자, 자기 머신 |
| 모니터링·SLA·온콜 | 서비스가 아님 |
| PII·GDPR | 데이터 수집·전송 0 |

## 3. 만약 나중에 "상용 SaaS"로 간다면 그때 (지금은 과설계)

§2의 항목 전부가 그때 살아난다. **지금 만들면 B(비개발자)가 옳게 지적한 낭비다.** 범주가 바뀌면 체크리스트도 바뀐다.

## 판정

**이 범주 기준, 배포해도 문제없다.** 챙길 것은 대부분 이미 안전(실측), 남은 건 **mac/linux 실측 하나**뿐이고 그것도 치명적 결함이 아니라 "미검증"이다(친구가 그 OS면 그게 첫 실측). 외부 공개(publish·GitHub)는 L5로 Mark 집행.
