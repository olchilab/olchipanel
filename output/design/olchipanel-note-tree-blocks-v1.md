# OlchiPanel 노트 페이지 트리·블록 이동 brief v1

- 모드: maintenance. 현재 OlchiPanel 노트 화면과 브랜드 토큰을 시각 정본으로 유지한다.
- 사용자 순간: Mark가 한 창에서 긴 기록을 페이지로 나누고, 페이지 안에서 문단 순서를 빠르게 고친다.
- 핵심 행동: 최상위 페이지 생성, 현재 페이지 아래 하위 페이지 생성, 트리 펼치기·접기, 경로 이동, 본문 최상위 블록 위·아래 이동과 드래그.

## 데이터 계약

- 기존 `memo.v3` 페이지는 내용·제목·순서를 바꾸지 않고 모두 최상위 페이지로 읽는다.
- 새 페이지는 선택 필드 `parentId`와 `collapsed`를 가진다. 존재하지 않는 부모·자기 부모·순환 부모는 저장 정규화에서 최상위로 복구한다.
- 페이지 삭제 시 자식 페이지를 함께 삭제하지 않고 삭제된 페이지의 부모로 한 단계 올린다.
- 본문 저장 형식은 기존 정제 HTML을 유지한다. 이동 단위는 편집기 바로 아래의 최상위 블록이며 임시 드래그 속성은 저장하지 않는다.

## 피함

- Notion의 아이콘·메뉴 순서·시각 스타일 복제
- 트리 도입을 이유로 기존 노트 자동 삭제·합치기·본문 변환
- 페이지 전체를 읽지 않아도 되는 상황에서 에이전트가 모든 하위 페이지를 반복 출력
- 드래그만 가능하고 키보드 또는 명시적 위·아래 버튼이 없는 조작

## 선호

- 오른쪽 목록은 얇은 disclosure 화살표와 들여쓰기로 관계를 표현한다.
- 현재 페이지 경로는 제목 위 한 줄에 작게 표시한다.
- 활성 블록에만 작은 이동 손잡이와 위·아래 버튼을 보여 편집 집중을 방해하지 않는다.
- 기존 평평한 표면과 OlchiPanel 청록 hairline을 유지한다.

## acceptance checks

- v3 fixture를 읽고 저장해도 제목·HTML·고정·순서가 보존되며 v4에서 `parentId:null`, `collapsed:false`가 명시된다.
- 정상 부모, 누락 부모, 자기 부모, 2노드 순환 fixture가 각각 예상 구조로 정규화된다.
- 하위 페이지 생성 후 부모의 화살표가 나타나고 접기·펼치기와 breadcrumb 이동이 동작한다.
- 한 페이지의 두 최상위 블록을 버튼과 드래그로 순서 변경한 뒤 재로드해 순서가 유지된다.
- 1440×900과 960×760에서 트리 들여쓰기, 제목, 편집기, 조작 버튼이 잘리거나 겹치지 않는다.
- 기존 노트 패널의 세로 하단 여백 32px 계약을 유지한다.
