# OlchiPanel 세로 탐색 구조 v1

- 모드: 기존 UI 고도화
- 목적: 세션 선택과 세션 작업 화면을 한 사이드바에서 예측 가능하게 탐색한다.
- 사용자 맥락: 데스크톱 앱을 기본으로 쓰되, 고배율과 좁은 화면에서도 같은 정보 구조를 유지한다.

## 구조

- 위: 세션 목록. 선택으로 본문 데이터만 바뀌며 메뉴 순서는 움직이지 않는다.
- 아래: 현재 세션 메뉴 `상황 · 플랜 · 요청 · 기록`.
- 맨 아래 공통 영역: `노트`. 세션을 바꿔도 같은 노트를 유지한다.
- 접힌 사이드바: 아이콘만 보이고 `title`과 `aria-label`로 이름을 제공한다.
- 모바일: 세션 목록과 메뉴를 하나의 드로어로 열고 닫는다.

## 피할 것

- 상단 탭과 사이드바 메뉴의 중복
- 선택한 세션이나 화면에 따라 메뉴가 재배열되는 동작
- 둥근 카드 묶음처럼 보이는 탐색 메뉴, 과한 그림자, 공급자별 강조색
- 공통 노트를 세션별 파일처럼 다시 불러오는 동작
- 고배율에서 우연히 줄바꿈되거나 잘리는 배열

## 검수 기준

- 본문 상단의 기존 5개 탭 줄이 없다.
- 사이드바에 세션 메뉴 4개와 분리된 공통 `노트` 메뉴 1개가 세로로 보인다.
- 세션을 바꿔도 선택한 노트와 내용이 바뀌지 않는다.
- 기존 세션별 `memo-<세션>.json` 파일은 삭제하거나 덮어쓰지 않는다.
- 플랜은 사이드바 오른쪽의 남은 너비와 높이를 계속 사용하고 5열을 유지한다.
- 200% 배율 데스크톱, 960px 중간 창, 760px 경계, 390px 모바일에서 잘림·우발적 줄바꿈이 없다.
- 노트가 2열이면 편집기 폭이 520px 이상이다. 그보다 좁아지기 전에 목록을 위로 올리고 편집기를 1열 전체 폭으로 전환한다.
- `scrollWidth === clientWidth`만으로 PASS하지 않고 편집기·목록의 완전 가시 영역과 실제 사용 폭을 함께 측정한다.
- 노트는 가로 폭과 별개로 패널 아래 여백을 제외한 남은 세로 높이를 사용한다. `note.bottom`이 workspace의 content bottom에 닿고 편집기와 목록의 하단 경계가 함께 이어지는지 전체 화면에서 확인한다.
- 시각 지적의 축이나 대상이 모호하면 수정 전에 `대상·가로/세로·보이는 증상`을 한 문장으로 되짚고, 합의되지 않은 축의 문제를 임의로 만들지 않는다.
